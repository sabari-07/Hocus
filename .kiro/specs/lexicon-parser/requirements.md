# Requirements Document

Spec: lexicon-parser

## Introduction

The parser turns one transcript (spoken or typed) into exactly one of three results: a control intent
("undo", "yes", "the first one"), a command frame whose pointing words are timed slots, or `no_action` with a
hint. Word lists live in data-only language packs for English, Hindi and Tamil. The parser is pure and
deterministic and lives in `packages/core` (`parser.ts`, `lexicon/*.ts`, `lint.ts`, `messages.ts`). It never
decides what a pointing word refers to; that is the resolver's job (fusion-engine).

## Glossary

- **Lexicon pack:** a data object (`LexiconPack`) with the words of one language: pointing words, verbs, colours, size words, numbers, control phrases, spatial words, fillers and homophones.
- **Frame:** a `CommandFrame`: an action name plus slot values, the language, the raw text and the unknown words.
- **Timed slot:** a slot value of type `deictic` or `anaphor`, carrying its spoken `order`, `tokenIndex` and `tWord`.
- **Implicit trigger:** a verb entry starting with `@` (`@color`, `@sizeUp`, `@sizeDown`, `@quantity`) that lets a value word select an action without a verb ("turn that green", "make it this big").
- **Quantity head:** an English word that turns "this"/"that" into a size gesture ("this big", "that size").
- **Postposition language:** a pack where spatial words follow their reference (Hindi, Tamil).
- **Control intent:** a dialogue instruction that is not an app action (`yes`, `cancel`, `undo`, `redo`, `otherOne`, `notThat`, `neither`, `choose`, `thisOne`, `whatWasThat`).

## Requirements

### Requirement 1: Commands become frames

**User Story:** As a user, I want ordinary phrasing like "make that bigger" to become one well-defined command, so that the engine knows what to do and which words need pointing.

#### Acceptance Criteria

1. WHEN a sentence generated by the test grammar is parsed, THE SYSTEM SHALL return a frame with the expected action and the expected literal values (scale factor, colour).
2. THE SYSTEM SHALL return every deictic and anaphor word as a timed slot with its spoken `order` and `tokenIndex`, and with `tWord` unset (`NaN`) until the engine fills it with `withWordTimes`.
3. WHEN several actions match, THE SYSTEM SHALL pick the action with the highest score `3 × matched verb tokens + implicit-trigger bonus + slot fit`; on a tie, the action with more verb tokens wins, then the action declared first.
4. WHEN the text is empty or matches no verb and no implicit trigger of any action, THE SYSTEM SHALL return `no_action` with a hint taken from the app's first example in the current language (English if none), and SHALL NOT throw for any input string.
5. WHEN an entity noun follows an indefinite article ("a pumpkin"), THE SYSTEM SHALL treat it as an entity type to create; after a definite article it SHALL be a reference to one object of that kind; after "every"/"all" it SHALL be the set of all objects of that kind; a bare noun SHALL be offered as both and the action's slots decide.
6. WHEN the text contains a user-given name or a unique object label ("make the ghost bigger"), THE SYSTEM SHALL return a `named` slot value instead of a pointing word.

### Requirement 2: Free word order and three languages

**User Story:** As a Hindi or Tamil speaker, I want to use my own word order and inflections, so that Hocus works in my language.

#### Acceptance Criteria

1. THE SYSTEM SHALL fill slots by kind, not by position: references are queued in spoken order and each slot takes the next value of its kind, in the action's slot declaration order.
2. WHEN the tokens of a Hindi or Tamil command are reordered, THE SYSTEM SHALL return the same action and the same slot values, ignoring token positions.
3. WHERE a pack sets `prefixMatch` (Tamil), THE SYSTEM SHALL accept a token that starts with a pack phrase of at least 3 code points (`பச்சையாக்கு` matches the colour `பச்சை`).
4. WHERE a pack sets `postpositions` (Hindi, Tamil), THE SYSTEM SHALL attach a spatial word to the reference before it; otherwise (English) to the reference after it.
5. THE SYSTEM SHALL mark Hindi and Tamil pronouns flagged `alsoAnaphor` on their slot value, so the resolver may fall back to discourse memory for them.
6. THE SYSTEM SHALL load packs as data only (no functions, no word-order rules); adding a language SHALL need only a new pack file and an entry in `lexicon/index.ts`.

### Requirement 3: Tolerant matching

**User Story:** As a user with an accent or a noisy recognizer, I want near-miss words to still work, so that I do not have to repeat myself.

#### Acceptance Criteria

1. THE SYSTEM SHALL normalize text before matching: Unicode NFC, lowercase, curly quotes to straight, punctuation (including `।` and `॥`) to spaces, and each single token replaced by its pack homophone ("dat" → "that", "colour" → "color").
2. THE SYSTEM SHALL tag tokens by greedy longest match; on equal length an exact match SHALL beat a prefix match, a prefix match SHALL beat a fuzzy match, and then the lower priority number SHALL win.
3. WHEN a Latin-letter token of at least 5 letters is one edit away from a verb, noun, colour or size phrase of at least 5 letters, THE SYSTEM SHALL accept it as a fuzzy match.
4. THE SYSTEM SHALL NOT fuzzy-match pointing words, names, numbers, ordinals or control words.
5. WHEN a token matches nothing, THE SYSTEM SHALL keep it as unknown and list it in the frame's `unknown` field.

### Requirement 4: Control phrases

**User Story:** As a user, I want short phrases like "undo", "yes", "no, the other one" and "the first one" to steer the dialogue, so that I can correct and confirm without menus.

#### Acceptance Criteria

1. WHEN the whole utterance, after dropping "please", the wake word and definite articles, equals a control phrase of the pack, THE SYSTEM SHALL return that control intent, checking in the order otherOne, notThat, whatWasThat, undo, redo, neither, yes, cancel, thisOne.
2. WHEN the utterance, also without "one" / "वाला" / "ஒன்று", equals an ordinal phrase ("the first one", "2"), THE SYSTEM SHALL return `choose` with the zero-based index.
3. THE SYSTEM SHALL detect control phrases before scoring actions, so a control phrase never becomes an app action.
4. WHEN a control phrase is only part of a longer sentence, THE SYSTEM SHALL NOT return a control intent for it.

### Requirement 5: Naming

**User Story:** As a user, I want to say "call this one Boris", so that I can refer to things by name later.

#### Acceptance Criteria

1. WHEN the utterance contains a naming phrase ("call", "name", "नाम रखो", "பெயர் வை"), an object reference and at least one unknown word, THE SYSTEM SHALL return the internal `__name` frame with a `target` slot and a `name` slot.
2. THE SYSTEM SHALL keep the original casing of the name and join a multi-word name with single spaces.
3. IF the naming phrase has no object reference or no unknown word, THEN THE SYSTEM SHALL continue with normal action scoring.

### Requirement 6: Values, implicit triggers, places and quantities

**User Story:** As a user, I want colour, size, place and "this big" words to fill the command, so that one short sentence says everything.

#### Acceptance Criteria

1. WHEN an action lists `@color` and a colour word is present, THE SYSTEM SHALL add 2 to its score; `@sizeUp`/`@sizeDown` with a size word SHALL add 2; `@quantity` with a quantity word SHALL add 5.
2. THE SYSTEM SHALL map size words to factors (up 1.25, down 0.8, much up 1.6, much down 0.6, double 2, half 0.5) and multiply several size words into one factor.
3. WHEN an object deictic is followed by a quantity head ("this big"), THE SYSTEM SHALL turn it into a quantity word and consume the head; Hindi and Tamil SHALL use their own quantity words (`इतना`, `இவ்வளவு`).
4. WHEN a spatial phrase ("next to", "between", "के पास") has a reference, THE SYSTEM SHALL return a `spatial` place value with one reference, or two for `between`; a plural reference SHALL end the search.
5. WHEN a required slot cannot be filled, THE SYSTEM SHALL lower that action's score by 1 for a missing single object (it may later be bound as an implicit "it") and by 2 otherwise, unless the slot is optional or has a default.

### Requirement 7: Lexicon lint

**User Story:** As an app developer, I want missing translations and phrase collisions flagged, so that every action works in every shipped language.

#### Acceptance Criteria

1. WHEN an app is linted, THE SYSTEM SHALL report an error for every action that has no trigger phrase (pack verbs plus app vocabulary) in one of `en`, `hi`, `ta`.
2. WHEN an app declares entities, THE SYSTEM SHALL report an error for every entity kind without nouns in one of the three languages.
3. WHEN one phrase triggers two or more actions in one pack, THE SYSTEM SHALL report a warning, except for the allowed pair `move|place`.
4. IF a pack has no deictic words, THEN THE SYSTEM SHALL report an error.
5. WHEN `npm run lexicon:lint` finds any error-level issue in the packs or in a registered app, THE SYSTEM SHALL exit with code 1.

### Requirement 8: Engine messages

**User Story:** As a user, I want Hocus to answer in my language, so that its questions and replies are clear.

#### Acceptance Criteria

1. THE SYSTEM SHALL keep every engine message (point first, did you mean, done, cancelled, undone, and the rest) as data in `messages.ts` for `en`, `hi` and `ta`, with `{a}`, `{b}` and `{list}` placeholders.
2. IF a message is missing for a language, THEN THE SYSTEM SHALL use the English text.
3. WHEN options are listed in a question, THE SYSTEM SHALL number them from 1 and join them with the language's word for "or".
