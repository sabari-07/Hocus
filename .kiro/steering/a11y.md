# Accessibility rules (target: WCAG 2.2 AA)

- Every interactive element has an accessible name, a keyboard path and a visible focus state
  (white 3 px ring, 2 px offset via `.focus-ring` / `:focus-visible`).
- **Modality parity:** anything doable by pointing + voice is doable with keyboard and mouse alone
  (scene list + actions menu, typed commands, number keys for ask options). A property test (P13) checks it.
- No color-only signals. The Wisp changes *shape* as well as color; chips carry text.
- Pointing targets ≥ 48 px on screen; other controls ≥ 24×24 CSS px (2.5.8). Every drag has a click alternative (2.5.7).
- Focus is never hidden under the speech bar or drawers (2.4.11). The Spellbook button is always in the same place (3.2.6).
- Live regions: polite for results, assertive for questions. Announce through `announce()` effects only.
- `prefers-reduced-motion`: remove pulses, glows, particle bursts and camera tweens; use instant changes.
- Never flash more than three times per second. Lightning and glows are slow fades.
- `<html lang>` follows the chosen language pack (`en`, `hi`, `ta`).
- The 3D canvas has `role="img"` with an `aria-label` summary; real interaction lives in DOM controls next to it.
- Run axe (`npm run test:e2e`) after UI changes and fix every serious or critical issue.
